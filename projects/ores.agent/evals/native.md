# Native agent integration

From `projects/ores.agent`, run `npm run eval:native -- /path/to/native.json`. Add an output-directory argument to choose where the runner saves its traces. Use `npm run eval:native -- --list` to list the 64 cases. Append `--case execute-report-trade` to run just the native NPV workflow, or pass comma-separated case IDs.

1. Copy `native.example.json` and `native-fixtures.example.json` to a private configuration directory. Set the PostgreSQL source, client binary path, and either a private libpq password file or `PGPASSWORD`. Start the source PostgreSQL instance first.
2. Set the agent config to use the clone fleet's TLS NATS port and a running inference endpoint. The Windows example expects NATS on 24005, HTTP on 24001, and monitoring on 24006. Point it at the existing service certificates. Set `credentials.json` to the source tenant and system accounts using `tenantUsername`, `tenantPassword`, `systemUsername`, and `systemPassword`. These accounts are copied with the database.
3. Fill `fixtures.json` with the source database's known book, portfolio, trades, completed NPV and risk runs, executable report definitions, and expected figures. The example values are illustrative. Give `partialRun` its own UUID if the source has no partial run. Set `scenario` to a distinct test name to seed a scenario. Add a `seed` command if the source also needs business records or report definitions. The command receives the clone database connection environment.

Each run creates a uniquely named database from the source. The default logical snapshot works while the source is in use. Set `clone.method` to `template` for PostgreSQL's file-copy path when no sessions are connected to the source. The Windows launcher starts the native services with separate ports, storage and JetStream state, and copies existing object storage into the runtime directory when available. On other platforms, supply start and stop commands for a dedicated fleet that set each service's database to `ORES_AGENT_CLONE_DATABASE` and NATS to the agent's configured test endpoint. Before the fleet starts, the runner pauses copied report jobs in the clone. It verifies the clone-only book through OreStudio and records active report jobs and new scheduled triggers before startup, after startup, and after the cases in `report-isolation.json`.

The runner fills missing partial-run, vega and scenario records in the clone with labelled test data, and publishes the FX and GBP market observations through native NATS. Source books, trades, clean NPV/rate results and executable report definitions must already exist or be provisioned by the configured seed command. New report executions still have to produce verified results from OreStudio. On legacy snapshots that only index ticks by series and time, set `clone.indexLegacyTicks` to build the series/coordinate/time index in the clone before the fleet starts. After the run the runner stops its fleet, drops the clone, and retains redacted conversations, seed evidence, logs, and case results under `build/output/agent-native/`.
